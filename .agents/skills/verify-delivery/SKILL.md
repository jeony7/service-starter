# 전체 검증

[요구사항 문서](../../../docs/REQUIREMENTS.md)의 필수 항목과 [앱 실행 안내](../../../app/README.md)를 기준으로 현재 결과물을 대조한다. 구현 계획을 실행 결과로 취급하지 않는다.

- 필수 UC별 정상·경계·실패 경로와 공통 제약의 적용 경로를 확인한다. 규칙 자체 테스트가 있어도 입력·수정·확정 경로가 그 규칙을 호출하는지 확인한다. 요구되지 않은 기능을 검증 범위를 채우기 위해 추가하지 않는다.
- AC의 자동 테스트·임시 스크립트·수동 확인을 구분하고 수단별 실행 세부와 실제 근거를 확인한다. 테스트 파일·이름·assertion·명령, API 요청/응답, SQL·바인딩 값·전후 조회 결과가 판정과 연결되는지 확인한다. Mock 테스트를 실제 DB·권한·네트워크 통합 검증으로 확대 해석하지 않는다. 기존 결과가 현재 코드·설정·입력·환경에 유효하면 재사용한다.
- 관련 기술 AC에서 실제 동시 경합을 만들었는지, 타임아웃의 지점·발생 조건·시간과 이후 상태를 확인했는지 대조한다. 상태 코드나 로그 한 줄만으로 데이터 불변 조건·롤백·후속 처리까지 통과로 표시하지 않는다. 확인하지 못한 부분은 해당 AC에 남긴다.
- 화면에서 API·저장·재조회로 이어지는 흐름을 확인한다. 기능 단위 테스트만으로 실제 연결 완료를 선언하지 않는다.
- 복잡한 업무 판단이 있으면 작은 사례의 기대 결과·선택한 풀이·실제 호출 코드를 대조한다. 예시 스크립트의 성공이나 임시 응답을 실제 기능 완료로 확대하지 않는다. 계산·입력 변경·저장·확정 중 해당 UC에 존재하는 경로에서 필수 조건이 유지되는지 확인한다. 탐색 중단·유효한 결과·제한된 후보 안의 최적·전역 최적을 구분한다.
- 지표가 필요한 항목만 평가한다. 지표 정의·선정 이유와 실제 측정 수단·입력·분모·집계 코드·비교 조건·결과를 대조한다. 예시 계산·수동 추정·실제 앱 측정을 구분한다. 필수 조건 위반을 품질 점수로 상쇄하지 않고 일반화 한계를 적는다.
- README의 설치·빌드·실행·주소·포트·DB 연결·조회·초기화 절차와 실제 동작을 확인한다. 초기 데이터 중복 방지·재시작 후 보존·컨테이너 볼륨을 해당 실행 방식에서 확인한다.
- 지정된 산출물 형식이 있으면 우선한다. 필요한 코드·lockfile·Wrapper·설정·Dockerfile·실행 안내를 확인하고 비밀 값·개인 DB·캐시·불필요한 빌드 결과를 제외한다. Docker가 없으면 JAR 검증을 Docker 검증으로 표시하지 않는다.
- 오류는 합의한 범위에서 수정·재검증하고 F/UC/AC 및 지표 상태를 갱신한다. 미실행·실패·차단과 남은 위험을 구분한다. 전체 완료와 일부 범위 완료를 구분해 보고한다.

전체 저장소를 반복 스캔하거나 이미 유효한 검사를 단계가 바뀌었다는 이유로 다시 실행하지 않는다. lint·포맷은 사용자 요청이 있을 때만 검사한다.
