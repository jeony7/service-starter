# 필요한 부분만 위임

- 작업량·독립성·전달/조율 비용을 보고 직접 수행, 한 부분 위임, 여러 담당자 분담 중 선택한다. 작은 작업이나 의존성이 높은 작업은 직접 수행한다.
- 화면·서버를 병렬 구현할 때는 같은 작은 범위의 API 입력/출력·오류·상태 계약과 파일 소유권을 먼저 정한다. 메인이 한쪽을 구현하고 다른 쪽만 위임해도 된다.
- 전달 내용: 목표, 관련 F/UC/C/AC, 참고 파일, 계약, 수정 범위, 검증 방법, 완료 기준. 전체 문서와 대화를 무조건 전달하지 않는다.
- 담당자는 배정된 범위만 수행한다. 별도 지시 없이 재위임하거나 다음 기능을 시작하지 않는다. 계약 변경이나 공유 파일 충돌은 메인에게 알린다.
- 반환 내용: 변경 파일, 동작 요약, 테스트/측정 수단과 실제 명령·결과, 미검증·차단, 통합 시 필요한 내용. 단순 완료 선언으로 대신하지 않는다.
- 메인은 공통 문서·공유 설정·계약 변경을 관리하고 실제 화면/API/저장 연결을 확인한다. 같은 조건의 유효한 검사 결과는 재사용하고 미확인 통합만 보충한다.
- 도구가 위임을 지원하지 않거나 현재 범위에서 위임이 허용되지 않으면 메인이 순차 수행한다.
