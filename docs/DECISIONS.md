# 설계 결정

구조·정책·알고리즘·데이터 계약 등 결과를 바꾸는 선택만 기록한다. 사소한 수정이나 전체 대화는 옮기지 않는다.

```text
D-ID — 결정 제목
관련 F / UC / C:
상황과 해결할 문제:
검토한 대안:
선택과 근거:
트레이드오프·남은 한계:
영향받는 API·상태·데이터 계약:
변경 시 재확인할 검증·지표:
```

여러 담당자가 작업할 때 현재 범위와 API 입력/출력·오류·상태 의미, 파일 소유권을 해당 결정 아래에 짧게 연결한다.

복잡한 업무 로직의 풀이를 선택할 때는 다음 내용 중 해당 항목을 위 기록에 포함한다. 단순한 기능에는 추가하지 않는다.

- 기준 풀이와 대안의 선택 근거: 입력 규모, 구현 비용, 조건 만족과 품질 목표. 규칙·작은 사례 원문은 REQUIREMENTS의 관련 기능을 참조한다.
- 선택한 풀이의 실제 절차: 상태, 후보 생성 범위, 조건 검사, 배정 변경, 선택·종료 규칙. 해당하지 않는 단계는 제외한다.
- 보장과 계산 비용: 정확한 풀이인지 휴리스틱인지, 고정한 범위와 제외한 경우, 반복·후보별 전체 재계산을 포함한 복잡도와 실행 제한.
- 연결한 검증·측정 근거: 관련 AC와 기준 구현 대비 결과. 아직 선택·구현·실행하지 않은 동작은 구분한다.
